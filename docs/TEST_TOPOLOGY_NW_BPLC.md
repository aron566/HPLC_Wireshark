```

├─ 代理A (TEI=2, 载波, L1)
│   ├─ STA (TEI=3, 载波, L2)
│   └─ STA (TEI=4, 无线, L2)
```

## 5. 关键协议点（防误判）

1. **南网 link_type 按 MMe 分裂，逐表查不可外推**（code-review-bot 已核表170 原文）：
   - mask `0x01`（bit0，载波频段 bit1-2=`0x06`）：关联确认 0x0031 / 关联指示 0x0034 / 代理变更确认·位图
   - mask `0x10`（bit4）：关联请求 0x0030 / 路由信息 / 代理变更请求
   - 国网同字段在 byte15 bit4 —— 两套协议位序不同，禁止互套
2. **IE 长度位宽**：南网独有机制（表216：bit7 标志 0=1 字节 / 1=2 字节长度）；本数据集全部用 1 字节长度，国网无此机制
3. **协议标注**：SPLC 解析器先注册时帧标 `nw_2026`，但 version=1 帧字段解析与 `nw_2021` 一致（bot 观察②，非缺陷）

构造口径：16/32bit 全部小端（L341），多字节字段非零可区分值（延迟 30s→`1E 00`、最大发现数 3→`03 00 00 00`），成功率 0-100 非零，脚本内置回读断言。

验证（tshark 实测）：FCCS 8/8、PB CRC 8/8、ICV 8/8；`nw_2021.mme.type` 0x0049/0x005D/0x0051/0x005E 全对（无 nw_2026 委托）；0x005E 帧解析器逐字段显示与构造一致（代理TEI 2 / 总数 2 / 条目 85/92/73/64）。

**已定案（原「观察」已闭环）**：位图 TEI 编码为 **0-based**（`TEI = 8×i + j`，无 +1），依据三点——
① 规约原文（南网 表196 / SPLC 第4部分 / 国网 HDC2.0 表102）均出现「**第 1 字节的第 0 比特 = TEI8**」，1-based 体系里不存在「第 0 比特」；
② 实帧同帧互证（南网实包帧14 bit1→TEI1、帧16/17 bit2→TEI2，与同帧「接收发现列表数(TEI n)」逐帧一致）；
③ 仓库 12 处实现（gw_2022/gw_2026/nw_2021 + 三份 Lua）全部 0-based。
→ **TEI 换算本身**解析器零改动（12 处实现本就 0-based）；原先位图字节 `C0 01` 是生成器旧 1-based 编码（`(t-1)//8`）所致，已改 0-based（`t//8`），现为 **`80 03`** = TEI7/8/9。
→ 附带修复：**Lua 解析器**心跳位图 tvb 偏移 `@20→@14`、保留 `@150→@144`（表196 body 8-137/138 + MMe 头 6B）—— 修正前位图整体错位 6 字节，实帧解析出的是帧尾 CRC；`wireshark_support_plugins/` 与 `release/wireshark_support_plugins/` 两份均已更新。
