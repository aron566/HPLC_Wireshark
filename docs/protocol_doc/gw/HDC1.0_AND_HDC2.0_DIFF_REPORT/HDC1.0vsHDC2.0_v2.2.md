### E. 方法论沉淀（供后续转换件比对复用）

1. **行粘连检测**：单元格内出现 `\d{1,3}\s+\d{3,}(?!\d)`（如 `10 1516`）或三段数字（如 `0 70 5`），或字段名单元格内同时含两个已知字段名 —— 均为跨页行粘连信号。误报较多（`20 420秒`、`33 36 或65 68 或…` 等带单位/枚举的正常内容也会命中），须人工裁定。
2. **题注前缀**：MinerU 可能输出 `## 表3 xxx`（带 markdown 标题前缀）。解析正则若要求题注在行首会**漏读** —— 本次即因此在复核初期误判"表3 题注丢失"，实为格式变化。
3. **图/表全集核对前置**：做版本增删判定**之前**，必须先核对两侧的图/表**全集**（含纯示意图 —— 它们没有 `<table>` 后继，最易被"仅统计表格题注"一类的提取规则整批漏掉）。
   漏掉的图不进清单，另一版里的同名图就会被误判成"独有/已移除"。
   > ⚠️ **本条已一般化**：v2.0 稿曾在此断言"仅收录 6 张图 / 漏计 84 张 / 旧版图题全部落入旧版独有"作为根因，
   > 该断言**与可观测事实矛盾**，已于 v2.1 撤回（见 §3 复核说明）。此处**只保留可复用的方法论，不复述具体数字与机制断言**。
4. **基线哈希比对**：必须做**字节级 sha256** 且**先做行尾归一化**再比较 —— 本次仓库副本（CRLF）与 `D:\doc` 源（LF）字节哈希不同但内容完全等价，误判会得出"基线漂移"的错误结论。
