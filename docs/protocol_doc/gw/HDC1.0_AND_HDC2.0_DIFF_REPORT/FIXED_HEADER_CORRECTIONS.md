## 应用建议（增量，不动既有产物）

1. 生成器 `parse_doc` 增加**同表片段合并**：按 caption 归属收集**所有** `<table>` 片段，
   逐片段的表头行（首格为「字段/名称/值/类型/参数/定义」）跳过，其余行按序拼接，
   再做 rowspan 展开与固定头计算。
2. 合并判据需**内容连续性**辅助：句子跨边界续接、字节号递进、字段名不重复。
3. 应用后重跑 `tools/gen_frame_catalog.py` 并**逐表比对固定头**，再决定是否更新 CATALOG。
4. ⚠️ **逐格比对不受影响**（它比的是同位置内容），只需修统计量。

## 五、✅ 影响面定案（2026-10-24 收窄测量后）

### 5.1 收窄口径
前两版测量把**枚举/取值类表**也算进来了（"固定头长度"对它们本无意义），故统计虚高。
本版**只取 CATALOG「★ 帧类型总表」实际收录的表**（四协议合计 **177** 张）作为口径。

### 5.2 结果
| 类别 | 张数 | 说明 |
|---|---|---|
| ★帧类型总表收录（口径内） | **177** | — |
| 其中固定头会变的 | **7** | **全部是南网BPLC 的枚举/取值类表**（PHR bits 扩展、版本、相线取值、开始关联标志位、万年历同步条目、关联请求的确认结果、信息单元类型）|
| 其中**真正的帧/报文类表**受影响 | **0** | ✅ |

### 5.3 结论
- ✅ **已入库的 CATALOG 的固定头长度**对**真正的帧/报文类表全部正确** —— 本缺口**不影响现有交付物**。
- ⚠️ 上表 7 张是**噪声**（`0B → 53B` 之类）：「固定头长度」对枚举表不是有意义属性，
  **不应据此订正**。若要彻底消除噪声，需在生成器里加**「帧/报文类表」判定**（比"固定头"语义更前置）。
- 📌 **国网 HDC1.0 表70 的 3640B 现象**：它只在**基线转件**（`260823_193255.md`）上出现 ——
  因为 CATALOG 取的是**最新转件**（`261023_152656.md`），其表70 首片段恰好完整 → 40B 正确。
  故该现象是**基线转件侧的表体切分差异**，**不是 CATALOG 的错误**。
- 📌 **仍建议做的改造（低优先级）**：生成器 `parse_doc` 增加「同表片段合并」，
  目的不是修 CATALOG，而是**让工具在基线件/异常件上也能给出正确固定头**，
  以及**顺带把 7 张枚举表从固定头统计里排除**（加「帧/报文类」判定）。
