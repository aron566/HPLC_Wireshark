## 1 范围

本文件规定了双模通信系统的物理层通信协议及服务。

本文件适用于双模通信系统通信单元之间的物理层数据交换。

## 3 术语和定义

## 3.1

协议数据单元 protocol data unit

两个对等实体之间交换的数据单元。

## 3.2

## 站点 station

通信网络中的从节点角色，其对应的设备实体为通信单元，包括电能表双模通信单元、I型采集器双模通信单元或双模II型采集器。

## 3.3

载荷子载波加载模式 payload subcarrier loading mode

对载荷在子载波上的调制参数、子载波使用集合及功率分配方式进行配置的传输模式，包含静态加载模式、动态功率加载模式与动态比特加载模式。

## 3.4

## 静态加载模式 static loading mode

调制参数由传输模式指示表确定、载荷功率保持恒定，且在通信频段内全量激活未被载波屏蔽表屏蔽的子载波用于数据传输的载荷子载波加载模式。

## 3.5

动态功率加载模式 dynamic power loading mode

调制参数由传输模式指示表确定，利用子载波选择表动态筛选参与传输的子载波集合，并通过载荷增益字段对所选子载波集合的载荷功率进行统一调整的载荷子载波加载模式。

## 3.6

动态比特加载模式 dynamic bit loading mode

调制参数由比特加载表动态确定各子载波组的启用状态及对应的调制阶数，且载荷功率保持恒定的载荷子载波加载模式。

## 3.7

有效子载波 valid subcarriers

由协议约定的起始和结束子载波索引界定可用于承载传输信号的子载波集合，该集合中的子载波包括数据子载波和导频子载波。

## 3.8

可用子载波 usable subcarriers

在有效子载波范围内除去法规约定屏蔽的固定子载波外可固定或者动态调度的用于承载传输数据的子载波集合，该集合中的子载波包括数据子载波和导频子载波。

## 3.9

子载波选择表 subcarrier selection table

用于标识各子载波组的启用状态的参数集合。。

## 3.10

比特加载表 bit loading table

用于标识各子载波组子载波启用状态与调制方式的参数集合。

## 5 高速载波物理层

## 5.1 概述

高速载波在单站点通信的上下行链路中，应支持采用正交频分复用（OFDM）技术进行报文传输，且载荷子载波加载模式应支持静态加载模式、动态功率加载模式和动态比特加载模式。

单站点接收端应具备同时检测两个通信频段的能力。

高速载波在多站点的下行链路中，应支持正交频分多址（OFDMA）模式或者时域聚合（TDA）模式进行报文传输，且载荷子载波加载模式应支持静态加载模式。

## 5.2.2 单站点发射端流程

对于发送单站点OFDM信号的发射机，发送端从数据链路层获取的帧控制信息与载荷数据，发射机的生成信号流程应符合图 1要求。

帧控制OFDM信号生成流程应符合以下要求：

a）发送端在接收到来自数据链路层的帧控制数据后，应依次执行包含Turbo编码、信道交织与帧控制分集拷贝的帧控制编码流程。其中，Turbo编码应符合5.6.2 节所述要求；信道交织应符合5.6.3 节所述要求；帧控制分集拷贝应符合5.6.4 节所述要求。

b）帧控制编码后的帧控制数据应依据帧控制分集拷贝模式中的调制方式进行星座点映射。

c）映射后的数据应进行IFFT变换并添加循环前缀及进行加窗处理，生成帧控制OFDM信号。

载荷OFDM信号生成流程应符合以下要求：

a) 发送端在接收到来自数据链路层的载荷数据后，应依次执行包含载荷扰码、Turbo编码、信道交织与载荷分集拷贝的载荷编码流程。其中，载荷扰码应符合5.8.2 所述要求；Turbo编码应符合5.8.3节所述要求；信道交织应符合5.8.4 节所述要求；分集拷贝应符合5.8.5 节所述要求。

b) 载荷编码后的数据应进行子载波加载与映射处理，若当前载荷为静态加载模式时，应依据表 13中所给出的传输模式在有效子载波上进行加载并进行子载波星座点映射；若当前载荷为动态功率加载模式时，应依据子载波选择表所指示的子载波进行加载，并依据数表 13中所给出的传输模式进行子载波星座点映射；若当前载荷为动态比特加载模式时，应依据比特加载表在有效子载波上进行加载并进行子载波星座点映射。

c)依据站点发送配置的通信频段将星座点映射后的数据分配至相应子载波位置进行IFFT变换并添加循环前缀，生成载荷OFDM信号。

发送端应依据帧控制字段中是否配置训练域，决定是否进行训练信号的处理。如果配置训练域，则应将训练域经过IFFT变换，并添加循环前缀，从而生成相应的训练信号。

在上述生成的帧控制OFDM信号之前插入前导信号，并根据帧控制字段指示的训练域插入位置，插入训练信号。

前导、帧控制、训练信号、载荷信号应按5.5 节所述要求构成完整的OFDM帧结构，经模拟前端处理后，可通过电力线信道进行传输。

## 5.2.3 单站点接收端流程

对于接收单站点OFDM信号的接收机来说，接收机处理流程应符合图 1要求，按照如下流程：

a) 接收端针对接收机接收的电力线信号进行自动增益控制调整，并完成通信频段的同步检测。

b) 根据实现同步的通信频段，对接收到的帧控制信号进行解调与译码处理，从而获取到帧控制信息。

c) 根据帧控制信息中所包含的载荷通信频段、解调与译码参数，完成对载荷的解调与译码，最终将电力线上的载波信号还原为原始数据信息，并传至数据链路层。

## 5.3.2 多站点 OFDMA 发射端流程

对于发送多站点下行OFDMA信号的发射机，其发送端从数据链路层获取帧控制、扩展帧控制信息以及各站点的载荷数据后，发射机的生成信号流程应符合图 要求。

帧控制与扩展帧控制数据的处理流程应与单站点帧控制数据的处理流程一致。

各站点载荷的OFDMA信号生成流程应满足以下要求：

a) 发送端从数据链路层获取各个站点载荷后，应分别对各站点的载荷进行编码，各站点载荷的编码方式及处理流程应与单站点载荷的编码方式及流程相同。

b) 针对各站点完成编码后的数据，应根据为每个站点分配的表 13中所给出的传输模式，执行分集拷贝操作，并进行子载波上的星座点映射；随后，依据各个站点分配的错误!未找到引用源。RU信息，将星座映射后的符号分配至对应的子载波上，并统一进行IFFT变换以生成OFDM符号，再添加循环前缀并进行加窗处理，从而形成各站点的载荷信号。

各个站点应根据其分配的RU信息，对训练域进行IFFT变换并添加循环前缀，生成相应的训练信号。

在上述流程中生成的帧控制信号之前应插入前导信号，在扩展帧控制信号之后应依次插入训练信号与载荷信号，并应按5.5.4 节所述要求构成完整的多站点OFDMA帧结构，经模拟前端处理后，该信号可通过电力线信道进行传输。

对于接收多站点下行OFDMA信号的接收机，接收机处理流程应满足图2要求，按照如下流程：

## 5.4.2 多站点 TDA 发射端流程

对于发送多站点下行TDA信号的发射机，其发送端从数据链路层获取帧控制、扩展帧控制信息以及各站点的载荷数据后，发射机的生成信号流程应符合图3要求。

帧控制与扩展帧控制数据的处理流程与单站点帧控制数据的处理流程相同。

各站点载荷的TDA信号的生成流程应符合以下要求：

a) 发送端从数据链路层获取各个站点的载荷数据后，应依据各站点的发送序号分别对其载荷进行独立编码，其编码方式及流程应与单站点载荷的编码方式及流程保持一致。

b) 针对编码后的数据，应依据当前站点所分配的表 13中所给出的传输模式进行分集拷贝与子载波星座映射；

c) 对完成子载波星座映射的符号，应依据当前站点所分配的通信频段，进行IFFT变换，并添加循环前缀，随后进行加窗处理，从而生成该站点对应的载荷OFDM信号。

d) 对各站点生成的载荷OFDM信号进行时域聚合流程处理。

各站点应依据其是否配置有训练域及其载荷分配的表 19中的通信频段来进行训练信号的处理；如果配置了训练域，则应将训练域经过IFFT变换并添加循环前缀生成训练信号。

在上述流程中生成的帧控制信号之前应插入前导信号，在扩展帧控制信号之后应依次按序插入各个站点的训练信号（如存在）以及载荷信号，并应按5.5.5 节所述要求构成完整的多站点 TDA 帧结构，经模拟前端处理后，该信号可通过电力线信道进行传输。

## 5.4.3 多站点 TDA 接收端流程

对于接收多站点下行TDA信号的接收机来说，其接收处理流程应符合图3要求，按照如下流程：

a) 各站点接收机通过电力线检测到信号后，应分别完成帧控制与扩展帧控制信号的解析。

b) 各站点接收机应基于解析得到的帧控制与扩展帧控制信息，获取与其站点对应的载荷所对应的报文接收时序、通信频段以及解调和译码所需的参数信息，并据此进行相应的解码与解调处理，最终将电力线上的载波信号还原为原始数据信息，并传至数据链路层。

## 5.5.4 物理层多站点OFDMA下行帧结构

物理层多站点OFDMA帧应用于单站点对多站点之间的报文传输，其帧结构示意图如图 17所示，其具体帧结构应符合图 18要求。数据帧应为每个用户配置对应的训练域（TF）。

OFDMA帧应支持同时向 2\~4个站点发送信号，每个站点应只支持1个物理块，物理块规格应只支持 PB72， PB136 和 PB264。

当不同站点生成的载荷OFDM符号数量不一致时，以当前帧内所有站点的最大载荷OFDM符号数为基准，对各站点载荷做长度补齐处理。

设站点i需要补齐的OFDM符号数为Pad\_Symbo\_Num(i)，该站点子载波调制方式对应的单载波比特数为Bit\_Len(i)（调制方式与比特个数对应关系见表 15），站点i需要填充的子载波数量为N\_Pad(i)，则站点i需填充的总数据比特长度Pad\_Len(i)按公式（1）计算，

$$
\text { Pad\_Len } (i) = \text { Bit\_Len } (i) * N \_ \text { Pad } (i) * \text { Pad\_Symbo\_Num } (i), i = 0, 1, 2, 3.
$$

根据各站点待填充数据比特长度，各站点分别按照多站点填充数据生成规则生成填充数据，并将其统一拼接至本站点载荷分集拷贝数据的末尾。填充数据所采用的调制方式，应与本站点载荷传输模式中的调制方式保持一致。

多站点填充数据生成规则与填充方式如下：

a) 按照5.8.2 节公式（2）伪随机发生器产生填充比特，伪随机序列发生器的初始状态置为全 1。

b) 将伪随机序列发生器循环左移 1 位，从状态寄存器低位开始取长度为 Bit\_Len(i)的比特，作为第一个待填充OFDM符号首个子载波的填充数据；再次将发生器循环左移 1 位，取对应长度比特作为该 OFDM 符号第二个子载波的填充数据。重复执行移位、取比特、填充操作，直至完成第一个待填充 OFDM 符号所有子载波的填充数据生成；

c) 继续将伪随机序列发生器循环左移 1 位，取指定长度比特，作为第二个待填充 OFDM 符号首个子载波的填充数据。循环执行上述操作，直至完成第二个待填充 OFDM 符号所有子载波的填充数据生成；

d) 按上述流程逐符号依次处理，直至完成 Pad\_Symbo\_Num(i)个待填充 OFDM 符号全部子载波的填充数据生成。。

## 5.6.1 帧控制前向纠错码流程

帧控制前向纠错码的生成流程应由Turbo编码、信道交织以及分集拷贝三部分构成。

## 5.6.2 帧控制 Turbo 编码

帧控制应采用码块长度 PB16 与码率1/2 的Turbo编码，最终输出的Turbo编码序列应为256比特。其中前128比特应为信息码，后 128比特应为校验码。

具体方法应符合5.8.3 节要求。

## 5.6.3 帧控制信道交织

帧控制的信道交织应在多次拷贝及信号传送到信道之前，对Turbo编码器输出的 256比特的编码序列进行随机化处理。

具体方法应符合5.8.4 章节要求。

## 5.6.4 帧控制分集拷贝

帧控制的分集拷贝应为后续星座点映射提供支持，其应将输入的256比特数据拷贝至频域子载波，所有帧控制符号均应采用QPSK调制方式。

帧控制（FC）长度应支持短 FC、标准FC和长FC三种模式，并可动态调整具体模式。频段1、频段 2、频段 4 及频段 6 的信标帧和 SOF 帧对应的三种 FC 长度应分别为 8、12 和 16；频段 0 和频段 5的信标帧和SOF帧对应的三种 FC长度应分别为2、4 和8；选择确认帧和网间协调帧的 FC长度应为标准FC 长度。FC长度的具体值应符合 QGDWXXX.42 帧控制域要求。

对于频段 0，可用子载波数量为 411，子载波编号范围应为 80 至 490；对于频段 1，帧控制可用子载波数为 131，子载波编号范围应为 100 至 230；频段 2 可用子载波数为 89，子载波编号范围应为 32至120；频段4可用子载波数为199，子载波编号范围应为 32 至230；频段5 可用子载波数为459，子载波编号范围应为32至490；频段6可用子载波数为 241，子载波编号范围应为 250至 490；

## 5.7 扩展帧控制前向纠错码

## 5.7.1 扩展帧控制前向纠错码流程

扩展帧控制前向纠错码流程应与帧控制前向纠错码流程一致，具体流程应符合 5.6.1 节的要求。

## 5.7.2 扩展帧控制 Turbo 编码

扩展帧控制的Turbo编码块长度应为PB16，码率应为 1/2，最终输出的Turbo编码序列应为256比特。其中前128比特应为信息码，后 128比特应为校验码。

具体Turbo编码方法应符合5.8.3 节的要求。

## 5.7.3 扩展帧控制信道交织

扩展帧控制的信道交织用于在多次拷贝及信号传送到信道之前，对 Turbo 编码器输出的比特位置进行随机化处理。

具体信道交织方法应符合5.8.4 节的要求。

## 5.7.4 扩展帧控制分集拷贝

扩展帧控制所占用的频段应与帧控制一致，其符号数量应由帧控制字段指定，且不超过帧控制的符号数。所有扩展帧控制符号应采用QPSK调制方式。

具体分集拷贝方法应符合5.6.4 节的要求。

## 5.8.4 载荷信道交织

## 5.8.4.1 信道交织步骤

Turbo编码后数据应保持编码前顺序，信息位在前，校验位在后（校验位p、q交错，p在前，q在后）。信道交织应包含下述4个步骤，其中K代表信息比特的数量，N-K代表校验比特的数量，K个信息比特会分成4个子块，每个子块的大小为K/4比特， N-K个校验比特分成4个子块，每个子块的大小为(N-K)/4比特。

## 5.8.4.2 信息码的交织

信息码的交织应符合如下流程：

a) 应将Turbo编码器输出的信息比特按列存入维度为K/4行4列的矩阵中，即该矩阵的第 1列存储的是编码器输出的前 K/4个比特，定义为区块 1，第2 列存储的是编码器输出的第 K/4+1到第K/2个比特，定义为区块 2，以此类推；

b) 应按行读取上述矩阵中的信息，每行4 个比特同时读出，第一轮读取时行地址应为（0, StepSize,2\*StepSize, …），第二轮读取时行地址应为（1, 1+StepSize, 1+2\*StepSize, …），以此类推，经过StepSize轮后全部行应读取完毕。

## 5.8.4.3 校验码交织

校验码的交织应符合如下流程：

a) 定义 T=(N-K)/4，类似于信息码的交织，应将 Turbo 编码器输出的校验比特按列存入维度为 T行4列的矩阵中；

b) 对于1/2码率，校验比特的读取应按步骤 c)进行，对于16/18码率，校验比特的读取应按步骤d)进行；

c) 应按行读取校验比特，第一轮读取时行地址应为 (offset， (offset+StepSize) mod T，(offset+2\*StepSize) mod T， …)，每轮读出 T/StepSize 行数据，然后第二轮首行应加 1，再重复 StepSize-1 轮，最后经过 StepSize 轮，共计读取 T 行数据；

d) 应 按 行 读 取 校 验 比 特 ， 每 轮 读 完 不 初 始 化 行 地 址 ， 而 是 从 开 始 持 续 读 取 (offset ，(offset+StepSize)mod T， (offset+2\*StepSize)mod T，…)，一直到 T 行读取完毕。信道交织用到的参数如表 11定义。

## 5.10.6 前导符号生成

前导应由SYNCP与SYNCM两部分组成，SYNCP符号数支持自适应配置，可配置符号数范围应满足5.5至10.5个符号，其中多站点的选择确认帧的SYNCP符号数应固定配置为10.5个，SYNCM符号数应固定为2.5个。SYNCP的定义应如公式（13）所示。

$$
S _ {\text {synCP}} (n) = \frac {1 0 ^ {3 / 2 0}}{\sqrt {\mathrm{N}}} \sum_ {k \in C} \cos \left(\frac {2 \pi n k}{N} + \frac {\pi}{8} \varphi ((\mathrm{k} + \mathrm{m}) \% 5 1 2) \right.\tag{23}
$$

其中， 为可用的载波集合，N取1024。m为初始相位标号，不同频段的具体m值应符合表 19的规定。

另外，前导SYNCP也可通过IFFT产生，IFFT的公式见公式（14），

$$
x (n) = \frac {1}{N} \sum_ {k = 0} ^ {N - 1} X (k) e ^ {j \frac {2 \pi n k}{N}}, \quad 0 \leq n \leq N - 1\tag{34}
$$

取复信号，见公式（15），

$$
X (k) = \left\{ \begin{array}{l l} e ^ {j \frac {\pi}{8} \varphi ((k + m) \% 5 1 2)} & \text { if } k \in C, 0 \leq k \leq N - 1 \\ 0 & \text { else } \end{array} \right.\tag{45}
$$

可以得到公式（16），

$$
S _ {s y n C P} (n) = 1 0 ^ {3 / 2 0} \cdot \sqrt {N} \cdot \operatorname{Re} \left\{I F F T (X (k)) \right\}\tag{56}
$$

即，SYNCP可由X(k)的IFFT变换取实部得到。

SYNCM=-SYNCP。其中，前导开始的0.5个SYNCP应是SYNCP的后半部分，最后的0.5个SYNCM应是SYNCM的前半部分。

## 6 无线物理层

## 6.1 概述

发送端：从数据链路层接收数据，经过系列的信号处理和变换，应采用 调制方式对编码后的数据进行处理并将形成的OFDM信号送入模拟前端并发送到空中；

接收端：将接收到的信号做相应的解调解码处理，最终将模拟信号还原为解码后数据信息，并送到数据链路层进行后续协议解析。

## 6.2.2 发射端流程

无线发送端流程，应符合以下要求：

a）发送端从数据链路层接收数据后，应通过三条独立的链路分别对SIG域数据、PHR数据和PSDU数据进行处理；

b）将SIG域信息按照分组码进行编码、符号填充和加扰处理；

c）将PHR信息进行Turbo编码、打孔、交织、分集拷贝处理；

d）将PSDU信息进行加扰、Turbo编码、打孔、交织、分集拷贝处理；

e）将经过处理的SIG、PHR、PSDU信息进行映射、加导频载波（Pilot）、直流（DC）载波和两端保护载波（Guard SubCarriers）、做N点IFFT，完成频域到时域的变换；

f）加入前导后，加入循环前缀；

g）进行加窗、DAC，经过上变频和功放，最后通过天线发送出去。

## 6.2.3 接收端流程

无线接收端流程，应符合以下要求：

a）接收数据经过LNA、下变频、滤波、得到基带数据；

b）完成同步，进行FFT变换得到频域数据；

c）使用频域数据（训练序列、导频）进行信道估计和频偏估计；

d）进行数据解调；

e）SIG域经过数据合并、（36,3）分组译码、解扰、解码后得到对应信息；

f）PHR经过分集合并、解交织、解打孔、Turbo译码，最终得到PHR信息；

g）PSDU经过分集合并、解交织、解打孔、Turbo译码、解扰，得到PSDU信息。

## 6.6.4 PHR 信道交织

在多次拷贝和传送到信道之前，PHR信道交织应将Turbo编码器输出的信息比特和校验比特进行随机化。

信息比特应分成4个子块，每个子块大小为K/4比特。信息比特按列写入K/4行4列的矩阵，按行读出。第一轮读(0, StepSize, 2\*StepSize…)行直到矩阵尾部；第二轮读(1, 1+StepSize, 1+2\*StepSize…)行直到矩阵尾部；经过StepSize轮后全部行读取完毕。

校验比特的交织：校验比特分成4个子块，每个子块大小为T=(N-K)/4比特。校验比特按列写入T行4列的矩阵，按行读出。第一轮读(offset, offset+StepSize, offset+2\*StepSize…) mod T行；第二轮读(offset+1,offset+1+StepSize, offset+1+2\*StepSize…) mod T行，每轮读T/StepSize行，经过StepSize轮后全部T行读取完毕。

每个成员码编码器应遵循下述算法：

a) 寄存器初始状态应按公式（18）进行设置，

$$
S 0 = \left[ S _ {0 1}, S _ {0 2}, S _ {0 3} \right]\tag{18}
$$

其初始状态应为 ；

b) 信息比特应持续输入至分量编码器（ENC2应输入交织后的信息比特），直至最后一位。此过程所得编码结束时的寄存器末状态应按公式（19）计算与定义。

$$
S N = \left[ S _ {N 1}, S _ {N 2}, S _ {N 3} \right]\tag{19}
$$

c) 定义矩阵M，当PB\_Size为520，72，16时，应按公式（20）定义：

$$
M = \left[ \begin{array}{c c c} 0 & 0 & 1 \\ 1 & 0 & 1 \\ 1 & 1 & 1 \end{array} \right]\tag{20}
$$

当PB\_Size为264，40时，应按公式（21）定义：

$$
M = \left[ \begin{array}{c c c} 1 & 0 & 1 \\ 1 & 1 & 1 \\ 1 & 1 & 0 \end{array} \right]\tag{21}
$$

当PB\_Size为136时，应公式（22）定义：

$$
M = \left[ \begin{array}{c c c} 0 & 1 & 1 \\ 1 & 0 & 0 \\ 0 & 1 & 0 \end{array} \right]\tag{22}
$$

d）复位初始状态 $S 0 ^ { \prime }$ 应按公式（23）计算，其中 SN是行向量，可通过查找表实现计算；

$$
S 0 ^ {\prime} = S N \times M\tag{23}
$$

e) 信息比特应重新输入至分量编码器，且编码器初始状态应设置为步骤d)中所计算的结果，此次编码后的末状态应符合公式（24）定义，

$$
S N ^ {\prime} = S 0 ^ {\prime}\tag{24}
$$

最终，Turbo编码的校验位应据此过程生成并输出。

## 6.7.6 PSDU 分集拷贝

PSDU的分集拷贝策略应与PHR相同，其区别在于PSDU的拷贝次数应设定为1次、2次或4次，PSDU支持多数据块，每个数据块的具体实现方式应符合6.6.5节的规定。当PSDU存在多数据块时，在分集拷贝次数为1时，各数据块的最后一个OFDM符号的部分子载波可能未填满，这时各数据块应独立对未填满子载波进行填充处理，每数据块的填充方式应符合6.6.5节的规定。

注：与PHR类似，交织器地址为载波编号，每个载波根据不同的调制模式承载对应的比特数，即若为BPSK调制，则1号载波承载数据比特1；若为QPSK调制，则1号载波承载数据比特1、2；若为16QAM调制，则1号载波承载数据比特1、2、3、4。

STF应对整个数据（5个OFDM符号长度）加窗，加窗后的STF 长度应为 5×IFFT 长度+1×滚降间隔。其前部的滚降间隔数据应为 STF 尾部数据的拷贝，将其乘以 $w _ { r i s e } [ n ]$ 后不应与任何信号重叠；其后部的滚降间隔个数据乘以 $w _ { \it f a l l } [ n ]$ 后，应与LTF 的滚降间隔个数据乘以 $w _ { r i s e } [ n ]$ 后相加；

LTF应对整个数据（2.5个OFDM符号长度）加窗，加窗后的LTF长度应为2.5×IFFT长度+1×滚降间隔。其前部的滚降间隔+0.5\*IFFT长度个数据应为LTF尾部数据的拷贝，将其前部滚降间隔个数据乘以$w _ { r i s e } [ n ]$ 后，应与STF后部的滚降间隔个数据乘以 $w _ { \it f a l l } [ n ]$ 后相加；前导LTF后部的滚降间隔个数据乘以$w _ { \it f a l l } [ n ]$ 后，应与第一个OFDM符号前部的滚降间隔个数据乘以 $w _ { r i s e } [ n ]$ 后相加；

SIG、PHR和PSDU 的每个OFDM符号均应添加循环前缀并加窗，每个OFDM符号前部的滚降间隔个数据乘以 $w _ { r i s e } [ n ]$ 后，应与其前面一个OFDM符号后部的滚降间隔个数据乘以 $w _ { \it f a l l } [ n ]$ 后相加，最后一个OFDM符号后部的滚降间隔个数据乘以 $w _ { \it f a l l } [ n ]$ 后，不应与任何信号重叠。
